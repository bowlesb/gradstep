# Local scientific AI prototype — 2026-10-17

Qwen3.5 4B is the stronger prototype candidate in this small application test. Neither it nor Gemma 4 E2B
passed the numerical figure checks cleanly. Keep this an explicitly experimental option; do not replace cloud
answers or promise iPhone suitability from these results. Provider spend for this work: **$0**.

## What was tested

The app's MLX engine, pinned 4-bit weights, actual tokenizers and processor, running on an **M1 Max MacBook Pro,
32 GiB RAM**. Same questions, source paper, selected LaTeX/caption and image files for each contestant; each model
selects excerpts within the same token budget. This evaluates the application pipeline, not an isolated model
leaderboard: different tokenizers can admit different paragraphs, and native image processors differ.

Six cases: DPO Figure 3's misleading caption; Mamba Figure 8 throughput values; the same Mamba question with only
the right panel; PRISM's architecture diagram; Mamba equation (4) with its exact LaTeX selected; and a DPO compute
question the excerpts cannot answer. Sources are existing verified arXiv reader bundles. No PDF or paper was sent
to a server. Questions, selections and input/image hashes: `tests/local-ai/cases.json`. Full local inputs and
outputs: `.artifacts/local-ai/cases/` and `.artifacts/local-ai/*-final.json`.

Configuration: MLX Swift LM 3.32.3, MLX 0.32.3, Swift Transformers 1.3.0; 3,072 input + 1,024 output tokens;
one figure, at most 1,024² pixels after resizing within 1,600²; 1,100 tokens reserved for the image; temperature
0.7, top-p 0.8, top-k 20, seed 42, thinking disabled. The final processor token count is enforced. Gemma retains
its pinned processor's 280 soft-image-token setting. Models and every downloaded file are pinned and hashed in
`apps/apple/LocalAI/Sources/LocalAI/Resources/models.json`.

These are single sampled answers, inspected against the source figures and the existing checked reference answers;
there is no blinded independent grader or statistical accuracy claim. Builds were also running on this Mac, so
latencies are indicative, not a clean performance leaderboard. Lab benchmarks generally use different inference
settings from this constrained, non-thinking, quantized prototype.

## Findings on the same questions

| Case | Qwen3.5 4B | Gemma 4 E2B |
|---|---|---|
| DPO plot/caption conflict | Reads colors and green line above 50%, but contradicts itself by also calling DPO the only line above 50%. Invents an interpretation involving GPT-4 as the comparison target. Fail. | Swaps DPO and Best-of-128 colors, follows the misleading caption, and misses the crossing. Fail. |
| Mamba full figure | Reads 1,814 correctly, but assigns 1,089 to Transformer instead of 364 and explains away the 5× claim incorrectly. Fail. | Says exact values are not labeled, although they are printed above the bars. Does not answer the numerical question. Fail. |
| Mamba right-panel crop | Reads 1,814 and the Transformer OOM limit correctly, but reads 364 as 354. Approximately correct 5× explanation; numeric extraction remains wrong. Partial. | Assigns 515 to both compared models; this is a different series. Fail. |
| PRISM mechanism diagram | Explains PPS → offline demand, CPR prediction and PSW weighting, and unchanged inference. Substantially useful, though not a complete description of every arrow. | Gives the broad caption-level mechanism, but invents a third part and misnames PPS. Less complete. |
| Mamba selected equation | Correctly identifies ZOH, continuous/discrete matrices, matrix exponential and identity. Useful basic explanation; not a complete account of input-dependent Δ, and some citations are loose. | Preserves the LaTeX but repeatedly says symbols are “likely” related to dynamics; includes C as an input to a rule that does not use it. Incomplete. |
| Unanswerable DPO compute cost | Explicitly says GPU hours / wall-clock numbers are absent. Pass. | Explicitly says the numbers are absent. Pass. |

The small **Qwen3 0.6B** text baseline is fast but failed the selected equation: it described both discrete matrices
as transformations of Δ. On the unanswerable question it asserted lower compute without saying the requested
numbers were absent. It has no image input. Do not position it as a trustworthy scientific explainer.

An additional **Qwen3.5 2B** check used five of the same cases, with network denied. Its process footprint was
about **3.85 GB**, a more plausible phone candidate than the two larger models. Quality was still mixed: it
identified the DPO caption conflict but missed the high-temperature crossing; read Mamba's 1,814 correctly but
invented a Transformer value and calculation; explained the broad PRISM mechanism with an incorrect interpretation
of flow-time visibility; and copied the selected equation correctly while misdescribing Δ. It correctly declined
to invent absent DPO compute numbers. Lower memory is not evidence of adequate scientific accuracy. Evidence:
`.artifacts/local-ai/qwen35-2b-*-measured.{json,log}`. The app's actual `LocalModelStore.download` fetched and
verified its 1,749,079,691-byte pinned package (`download-2b.log`).

## Timing and memory

Across the four figure/diagram cases in the final matched run:

| Model | First text, engine | Whole engine answer | Peak MLX allocation |
|---|---:|---:|---:|
| Qwen3.5 4B | 5.6–6.8 s | 14.5–16.9 s | 4.12–4.24 GB |
| Gemma 4 E2B | 7.4–8.2 s | 10.1–11.6 s | 6.84–6.97 GB |

Gemma's shorter answers finish sooner; that does not mean they answer the question better. These times start after
file verification and exclude the model download; the full CLI calls added about 2–3 seconds for verification and
startup in that run. The earlier 73–118 second Gemma startup was mostly our repeated tokenization, not model speed.
Candidate paragraphs are now counted independently with a final exact whole-prompt check; measured context
selection fell to roughly 2 seconds for Gemma and 0.1–0.2 seconds for Qwen.

**MLX allocation is not total app memory.** Separate `/usr/bin/time -l` runs with all network access denied reported
peak process footprint of **6.72 GB for Qwen4B** and **6.70 GB for Gemma** on the Mamba panel. Retain both counters;
do not infer an iPhone memory limit from MLX alone. Raw evidence: `qwen35-4b-process.{json,log}` and
`gemma4-e2b-process.{json,log}` under `.artifacts/local-ai/`. Physical iPhone tests remain paused. No battery,
thermal, jetsam, sustained-use or phone latency acceptance has been performed.

## Why preserve failures

The first 512²-pixel run misread even the Mamba peak. Increasing the bound to 1,024² and using a tight panel crop
improved Qwen's result, but did not make it exact. Earlier answers remain as `*-bounded.json`; they are not erased
or presented as successful runs. The original equation-only chat prompt did not supply the exact equation;
`mamba-equation-selected` exercises the actual equation view's input contract. It is a separate case, not a silent
replacement of that earlier result.

Use selected LaTeX plus relevant text and a figure/panel bitmap, as proposed. The available structured source is
the device's reader bundle; this does not reintroduce Mathpix. A future zoom/crop refinement can spend more image
tokens on a specific region, but it needs its own correctness checks. For now the app offers prose explanations;
local symbol tables, interactive generated diagrams and proposed crop boxes are not implemented.

## Reproduce without provider calls

Build the probe using Xcode so MLX's Metal library is packaged (plain `swift build` omitted it in this environment):

```sh
cd apps/apple/LocalAI
xcodebuild -scheme LocalAIProbe -configuration Release -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath ../../../.artifacts/local-ai/probe-build build
cd ../../..
.artifacts/local-ai/probe-build/Build/Products/Release/LocalAIProbe \
  qwen35-4b .artifacts/local-ai/models download
/usr/bin/time -l /usr/bin/sandbox-exec -p '(version 1) (allow default) (deny network*)' \
  .artifacts/local-ai/probe-build/Build/Products/Release/LocalAIProbe \
  qwen35-4b .artifacts/local-ai/models .artifacts/local-ai/cases/mamba-panel.json \
  .artifacts/local-ai/cases/mamba-panel.png
```

Input JSON contains `question`, optional `selection`, `paper` as original `[¶N]` text, `focus`, and `action`.
The final optional argument is one image file. A fresh checkout needs its own verified reader inputs; model weights
and complete paper bundles are intentionally not committed. Downloaded model licenses remain those of their model
makers; see each pinned repository's card. Nothing here changes the app's cloud processor/default or credits.
